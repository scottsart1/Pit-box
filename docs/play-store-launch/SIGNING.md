# Play App Signing and existing installs

The existing direct-download Android APK is signed with certificate SHA-256 `20c2751e5c0ede43a2442331336b990433e53d9e512f3f1bca3e8d5bee4c6983`. That is the **app signing key** needed on the APKs delivered by Google Play if users are to update an existing installation without uninstalling and losing app data. The certificate on the AAB uploaded to Play is an **upload key**; matching that certificate alone does not preserve the update path. See [Android's signing guide](https://developer.android.com/studio/publish/app-signing) and [Play App Signing guidance](https://support.google.com/googleplay/android-developer/answer/9842756).

`prepare-play-bundle.yml` is a manually triggered, `main`-only workflow. It builds an AAB with the existing release-environment key, verifies the AAB's public certificate and native ELF alignment, and retains the signed bundle as a GitHub Actions artifact. It does not upload to Play or publish an APK. Review the PR and merge the preparation changes before running it.

Play Console already reports an app signing key **in use** for this draft app. Its Digital Asset Links example displays a certificate fingerprint different from the existing direct-download APK. This is evidence of a likely mismatch, but the current signing certificate still needs an independent fingerprint check. Before any Play release, use the Console's **Change key** path to provide the existing app signing key if the current fingerprint is indeed different. The Console warns that previously installed internal/closed-test builds would need reinstalling after such a change; there are no test builds or opted-in testers currently. The key transfer must use Play Console's documented encrypted PEPK flow or equivalent option shown by Google. Do not put the keystore or passwords in a PR, Actions artifact, issue, chat, or website. After the change, compare Play Console's **app signing certificate** fingerprint with the value above before adding an AAB to any release. A later separate upload key is recommended; changing the upload key does not change the app signing certificate.

Before closed testing, install a direct-download APK with saved data, then install the Play-delivered higher-version build over it on the same device. Verify profiles, history, settings, and API keys. This remains untested. Also verify the release bundle's manifest, generated APK 16 KB ZIP alignment, and a 16 KB page-size runtime device or emulator; the source APK ELF inspection is not sufficient evidence for those checks.
